# musk-review

一个面向产品方案、技术架构、增长策略和内部 memo 的第一性原理评审 skill。

它不是角色扮演，而是一个更像高压评审会的决策工具：

- 先下结论
- 找真实瓶颈
- 明确该砍什么
- 最后直接拍板

适合那些你不想再看“中性但没结论”的分析，而是想把模糊方案压成明确决策的场景。

## 安装

```bash
npx skills add https://github.com/RealFelixWang/musk-review-skill --skill musk-review
```

## Skill 路径

```text
.claude/skills/musk-review
```

## 能做什么

- 用第一性原理重审方案
- 在优化前先删复杂度和无效范围
- 找出真正限制结果的主瓶颈
- 把模糊方案压成清晰决策
- 把过宽的方案重写成更尖锐、更可执行的版本

## 典型场景

- 产品方案评审
- 技术架构评审
- 增长策略评审
- 内部 memo 评审
- 把“大而全”的方案改写成一个更可能被批准继续做的版本

## 案例

### 产品方案评审

```text
帮我用马斯克式的方式评审这个 AI 会议助手方案。现在想做会议转录、自动总结、待办、周报、销售评分、知识库问答、邮件起草。团队 4 个人，计划 3 个月上线。
```

你应该预期它给出：

- 一个直接结论，告诉你这是不是明显过载
- 一个最该先解决的主瓶颈
- 一份明确的删减建议
- 一个更尖的第一版 wedge

### 技术架构评审

```text
请用高压评审会的方式看这个实时语音 AI 架构。我们现在想上三云、全链路 Kafka、多套微服务，但未来 6 个月大概只有 500 并发通话。
```

你应该预期它给出：

- 这套系统是不是 overbuilt 的明确判断
- 真正瓶颈在哪，而不是泛泛而谈
- 一个更适合当前阶段的简化架构

### 增长策略评审

```text
请像高压评审会一样评审这套增长策略。我们现在 MRR 2 万美元，打算同时做 SEO、联盟、YouTube、X、Reddit、Product Hunt、冷邮件和播客赞助，但留存一般。
```

你应该预期它给出：

- 这到底是增长问题还是留存问题
- 哪些渠道扩张应该先砍掉
- 哪一个增长循环最值得先验证

### Rewrite 模式

```text
把这个方案重写成一个更像会被批准继续做的版本。现在它想做平台、做多入口、做太多功能。
```

你应该预期它给出：

- 一个目标用户
- 一个核心痛点
- 一个核心工作流
- 一个主要入口
- 一个主成功指标
